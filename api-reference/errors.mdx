## Formato de error

```json
{
  "error": {
    "code": "insufficient_scope",
    "message": "La integración no tiene el permiso necesario"
  }
}
```

El objeto puede incluir `details` con información adicional.

| HTTP | Interpretación y acción |
| --- | --- |
| 400 | Revisa parámetros, cuerpo o cursor. |
| 401 | Revisa la API key y comprueba que siga activa. |
| 403 | Solicita el scope necesario. |
| 404 | Comprueba el identificador y su pertenencia a tu empresa. |
| 409 | Revisa duplicados o conflictos. `duplicate` puede incluir `details.existingId`. |
| 415 | Envía `Content-Type: application/json`. |
| 422 | Revisa campos, referencias, reglas de negocio o reutilización de idempotencia. |
| 429 | Espera el tiempo indicado por `Retry-After`. |
| 500 | Reintenta con espera progresiva; conserva la misma clave de idempotencia en los POST. |

## Límite de solicitudes

El límite predeterminado es 300 solicitudes por minuto por API key. Consulta `X-RateLimit-Limit`, `X-RateLimit-Remaining` y `X-RateLimit-Reset`. Al excederlo, la API responde `429` con `Retry-After`.

Evita reintentar errores de validación sin corregir la solicitud. Para errores transitorios, limita los intentos y aplica una espera progresiva.
